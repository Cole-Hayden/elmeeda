# Issue Tracker

A Python backend that validates breakdown issues and works out their job, labor hours, parts, and eligible vendors, backed by Postgres. Requires [uv](https://docs.astral.sh/uv/) and Docker.

## Run it

```bash
cp .env.example .env
```

```bash
docker compose up -d --wait
```

```bash
uv run alembic upgrade head
```

```bash
uv run uvicorn issue_tracker.main:create_app --factory --port 8001
```

Interactive API docs are at http://127.0.0.1:8001/docs.

## Run the frontend

The dev server sends `/api` requests to the backend on port 8001. Opening the page creates an issue.

```bash
cd frontend && npm install && npm run dev
```

## Load the mock data

This loads the fictional trucks, repair shops, and Truck 214 scenario. Run it again to reset between demos, or on a new day, because the scenario uses the date it was loaded. It deletes all bookings, trucks, shops, jobs, and any issue attached to a truck.

```bash
uv run python -m issue_tracker.infrastructure.seed
```

To demo a shop failing, take away its open bays after the agent has offered it:

```bash
docker compose exec db psql -U issue_tracker -d issue_tracker -c "UPDATE maintenance_shops SET open_bays = 0 WHERE name LIKE 'Rockdale%';"
```

## Create an issue

Send whatever is known about the breakdown. Every field is optional, so a request with no body also creates an issue. `truckUnitNumber` must match an existing truck, so load the mock data first.

```bash
curl -i -X POST http://127.0.0.1:8001/issues -H 'Content-Type: application/json' -H 'Idempotency-Key: demo-1' -d '{"truckUnitNumber": "214", "problem": "coolant_leak", "location": {"description": "I-55 near Joliet, IL", "latitude": 41.49, "longitude": -88.195}, "neededBy": "2026-11-07", "maxDistanceMiles": 30, "maxBudget": "1500.00", "symptoms": "Coolant is leaking under the engine.", "contact": {"name": "Fleet Dispatch", "phone": "555-0100"}}'
```

Set `neededBy` to today or later. This request returns status `201` and asks for the one detail still missing. The ID is generated by the server:

```json
{"issueId": "3f2b8c1e-6a4d-4e7b-9c10-2d5f8a7b1e34", "status": "needs_info", "missingDetails": ["drivable"], "towRequired": false, "truck": {"unitNumber": "214", "...": "..."}, "details": {"...": "..."}, "job": {"jobCode": "COOLANT_LEAK_GENERIC", "...": "..."}, "options": [], "excluded": []}
```

| Field | Required before vendors are matched | Notes |
| --- | --- | --- |
| `truckUnitNumber` | Yes | Must match an existing truck |
| `problem` | Yes | `coolant_leak`, `tire_blowout`, `brake_failure`, or `unknown`, which leads to a diagnostic job |
| `location` | Yes | `description`, `latitude`, and `longitude` |
| `drivable` | Yes | |
| `neededBy` | Yes | Today or later, in Central time |
| `maxDistanceMiles`, `maxBudget` | Yes | |
| `symptoms` | Yes | The driver's own words |
| `contact` | Yes | `name` and `phone` |
| `loaded`, `hazmat` | Only if a tow is needed | A tow is needed if `drivable` is false or `problem` is `brake_failure` |
| `odometerMiles`, `faultCodes` | No | `faultCodes` is a list of J1939 `spn` and `fmi` values |

An unknown truck or an invalid value returns `422`, and nothing is saved. If the database is unavailable, the response has status `503`.

The `Idempotency-Key` header is optional. Repeating a key returns status `200` with the original issue, and ignores the new body, so retries can't create duplicates.

## Update and read an issue

Send details as they become known. Only the fields sent are changed, and a null value leaves a field as it is.

```bash
curl -i -X PATCH http://127.0.0.1:8001/issues/<issueId> -H 'Content-Type: application/json' -d '{"drivable": true}'
```

```bash
curl -i http://127.0.0.1:8001/issues/<issueId>
```

Both return the same response as creating an issue, calculated from current data. An unknown ID returns `404`, and updating a booked issue returns `409`.

| `status` | Meaning |
| --- | --- |
| `needs_info` | `missingDetails` lists what to ask next |
| `options_ready` | `options` lists vendors with `openBays`, `distanceMiles`, `earliestStart`, and an `estimate` with its `labor`, `parts`, and `tow` breakdown |
| `no_vendor` | No vendor qualifies, and a person needs to step in |
| `booked` | The issue has a booking |

Vendors that aren't offered are in `excluded` with the first rule they failed, checked in this order: `job_not_offered`, `make_not_supported`, `no_tow_service`, `hazmat_not_supported`, `too_far`, `over_budget`, `no_open_bay`, `starts_too_late`.

All jobs, parts, prices, and vendors are fictional. Until a shop diagnoses the truck, every price is an estimate, and `requiresDiagnosis` flags jobs where the quote covers diagnosis only.

## Check the database

Postgres listens on `127.0.0.1:5434`.

```bash
docker compose exec db psql -U issue_tracker -d issue_tracker -c 'SELECT * FROM issues;'
```

## Architecture

Dependencies point inward, so the domain knows nothing about HTTP or SQL.

| Path | Responsibility |
| --- | --- |
| `src/issue_tracker/api/` | HTTP routes and response schemas |
| `src/issue_tracker/application/` | Use cases, triage, and the repository interfaces |
| `src/issue_tracker/domain/` | The `Issue`, `Truck`, `Job`, `MaintenanceShop`, and `Booking` entities, plus job selection, quote, and vendor rules |
| `src/issue_tracker/infrastructure/` | SQLAlchemy models, repository implementations, and fictional mock data |
| `src/issue_tracker/main.py` | App factory that wires the layers together |
| `frontend/` | React UI |
| `migrations/` | Alembic schema migrations |
| `openspec/` | Specs and change proposals |
